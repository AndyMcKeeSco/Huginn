# User Research

## Purpose
Answer desirability/usability uncertainty through **primary contact with users** — producing
observations (not opinions) that can become Evidence.

## When to use
- When existing knowledge cannot settle a desirability/usability question.
- To observe interaction with a lightweight prototype.

## When NOT to use
- When desk research suffices (cheaper) — try `knowledge-research` first.
- For technical feasibility (use `technical-investigation`).

## Inputs
- A Test's Learning Objective; participant access; a study protocol; any prototype (artifact).

## Definition of Ready
- A protocol, recruited participants, and ethics/consent in place.

## Methodology selection
- **Continuous Discovery interviewing / JTBD**; **usability studies**; **observation**;
  mixed-method where triangulation helps.

## Process
1. Run the study per protocol; capture recordings/notes as **artifact references**.
2. Record **observed behaviour** (what users did/said/chose), not interpretations.
3. Note conditions and limitations (sample, setting).
4. Hand observations + provenance to `evidence-appraisal`.

## Structured output
Artifact references and behavioural observations, ready for Evidence appraisal.

## Quality criteria
- Observations are behavioural and specific; consent/ethics honoured; limitations recorded.

## Definition of Done
- Appraisable observations tied to the Learning Objective.

## Failure modes
- Leading questions; recording opinion as fact.
- **Treating a prototype as Evidence** — it is an artifact; only observed interaction produces
  Evidence.

## Escalation / governance
- Ethics/consent issues halt the study and escalate; provenance is mandatory.
